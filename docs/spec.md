# وثيقة مواصفات طبقة المحادثة
## منصة السياحة الذكية في سوريا — الإصدار 1.0

---

## 1. المبدأ الحاكم

طبقة المحادثة هي «منسّق ومترجم» بين المستخدم وبين طبقتي التوصية والتخطيط.
تفهم اللغة وتدير الحوار وتصوغ الأجوبة، لكنها:
- **لا تخترع معلومات أبدًا** — كل حقيقة (اسم مكان، تقييم، سعر، وقت دوام، مسافة)
  تأتي حصرًا من استدعاء أداة.
- **لا تحسب** — كل رقم (مسافة، وقت، كلفة، ترتيب) مصدره الطبقات المتخصصة.

## 2. المتطلبات العامة (إلزامية)

### 2.1 اللغة
- الرد دائمًا بلغة رسالة المستخدم الأخيرة. إذا بدّل اللغة منتصف المحادثة، يُتبَع فورًا.
- فهم العامية السورية والشامية كاملًا: «بدي»، «شو»، «شلون»، «هلق»، «منيح»، «لكان»،
  «ياه»، «هدول»، «هيدا» — والرد بعربية سلسة قريبة من المحكية المهذبة، ليست فصحى جامدة.
- فهم الجمل المختلطة عربي/إنكليزي دون أي تعليق على الخلط.
- أسماء الأماكن تُعرض بالعربية مع الإنكليزية بين قوسين عند الحاجة، وبالعكس للأجنبي.

### 2.2 قواعد إدارة الحوار
1. **سؤال واحد كحد أقصى في الرد الواحد.** ممنوع سلسلة أسئلة.
2. **الجمع فقط — لا استدعاء ولا عرض أماكن/خطط (قرار المالك، مُحدَّث).** عرض
   الأماكن والخطط **ليس شغل طبقة المحادثة** — التوصية والتخطيط يجمعان الحقول
   الإلزامية (المدينة + التصنيفات + الميزانية + المجموعة [+ المدة للخطة]) بسؤال
   واحد لكل دور، وحين يكتمل الجمع **تتوقف الطبقة عند تأكيد الجاهزية فقط** (بلا
   استدعاء `recommender.search`/`planner.build` وبلا بطاقات/خطة). الحالة
   المتراكمة (ConversationState) هي بالضبط ما "يُسلَّم" لطبقة التوصية/التخطيط —
   تُعرض بقسم منفصل تمامًا عن نص المحادثة بواجهة الاختبار (`web/lab.html`)، لا
   داخل رد الشات. عند تهرّب المستخدم مرتين متتاليتين نتوقف بما توفّر ونصرّح بذلك
   («خلص، صار عندي كل يلي بلزم لطلبك»/«جمعت يلي قدرت عليه»). أما الاستعلام
   المباشر (تفاصيل مكان بالاسم) فيبقى يُجاب فورًا من الأداة دون جمع — هذا وحده
   ما زال يستدعي وأداة ويعرض نتيجتها كما هي.
3. **جمع تدريجي لا استجواب.** يُستنتج ما يمكن: «مع أطفالي» = عائلة،
   «ميزانية محدودة» = منخفضة، «خطيبتي» = زوجان.
4. **كل رد ينتهي بخطوة تالية واضحة** (اقتراح، خيار، سؤال واحد).
5. **الصراحة عند التعارض.** طلب غير واقعي (أماكن متباعدة بيوم، مكان مغلق) →
   مصارحة لطيفة + بديل. ممنوع بناء خطة غير قابلة للتنفيذ إرضاءً.
6. **زمن الرد:** ≤3 ثوانٍ للاقتراحات، ≤6 ثوانٍ للخطة.

### 2.3 حالة المحادثة (Conversation State)
كائن يُحدَّث مع كل رسالة، يُخزَّن في Redis بمفتاح الجلسة، ويُمرَّر كاملًا لكل استدعاء:

```json
{
  "destination": ["اللاذقية"],
  "dates": null,
  "duration_days": 3,
  "budget_level": null,
  "group_type": "friends",
  "group_size": 4,
  "interests": ["tag:sea", "tag:nature"],
  "pace": null,
  "excluded_place_ids": [],
  "saved_place_ids": [],
  "current_plan_id": null,
  "language": "ar"
}
```

**القواعد الأربع الحاكمة:**
1. **الوراثة:** معلومة ذُكرت مرة لا يُسأل عنها ثانيةً. (اختبار قبول: معلومة الرسالة 1
   محفوظة في الرسالة 20).
2. **التصحيح الفوري:** «لا خليها يومين مو تلاتة» → تحديث مباشر + ذكر التحديث بجملة.
3. **الاستنتاج قبل السؤال.**
4. **الإزالة الصريحة استثناء مقصود من الوراثة، وإعادة البدء الكاملة تتطلب
   تأكيدًا صريحًا أولًا** — التفاصيل والأمثلة بـ §2.6.

### 2.4 ذاكرة العمل (Working Memory) — تُحدَّث بعد كل رد إلزاميًا
```json
{
  "last_recommendations": [
    {"pos": 1, "place_id": "p17", "name_ar": "قلعة دمشق", "name_en": "Damascus Citadel"},
    {"pos": 2, "place_id": "p42", "name_ar": "الجامع الأموي", "name_en": "Umayyad Mosque"}
  ],
  "last_mentioned_place": "p42",
  "current_plan": null,
  "last_bot_action": "showed_recommendations"
}
```
- أي رد يعرض قائمة → تُكتب في last_recommendations بترتيبها.
- أي حديث عن مكان واحد → يُكتب في last_mentioned_place.
- أي خطة تُبنى أو تُعدَّل → تُكتب في current_plan.

### 2.5 شكل الجواب (الرد المنظم للواجهة)
```json
{
  "reply": "نص قصير (سطر–سطران) ينتهي بخطوة تالية",
  "cards": [/* أماكن بشكل contract.md — أو null */],
  "plan": {/* خطة بشكل contract.md — أو null */},
  "comparison": {/* جدول مقارنة — أو null */},
  "state": {/* الحالة المحدثة */}
}
```
- النص قصير — البطاقات والخط الزمني يحملان الثقل.
- الاعتذار عن النقص صراحةً («ما عندي معلومة مؤكدة») — ممنوع التخمين.

### 2.6 تعديل المعلومات المجموعة وإعادة البدء (طلب المالك)
يُفحص هذا المسار **قبل** توجيه النية الطبيعي (يُنهي الدور فورًا إن انطبق)، لأن
الاستخراج العادي أعلاه قد "يضيف" نفس الاسم المذكور للتو قبل أن تُفحص نية الإزالة.

- **إزالة صريحة (استثناء مقصود من قاعدة الوراثة):** فعل إزالة (شيل/احذف/الغي/
  remove/cancel/delete) يسبق مباشرة اسم مدينة أو كلمة اهتمام **موجودين فعلًا
  بالحالة** (نافذة ~12 محرفًا قبل الاسم، نفس أسلوب كشف النفي بـ
  context_extractor.py) يزيل تلك القيمة فقط من `destination`/`interests` — لا
  يُفهَم كإضافة رغم ذِكر الاسم بالنص. مثال: «بدي الغي دمشق» يزيل دمشق؛ «شيل
  دمشق وضيف حلب» يزيل دمشق فقط ويضيف حلب (بالاستخراج العادي) بنفس الرسالة —
  الفعل يجب أن يسبق الاسم الصحيح تحديدًا. الرد: تأكيد الإزالة + دعوة للمتابعة.
- **استثناء الخطة القائمة:** رسالة تذكر «الخطة»/«خطتي»/plan صراحة («شيل قلعة
  دمشق من الخطة») لا تُفهَم كإزالة وجهة من الحالة المجموعة، حتى لو تضمّن اسم
  المكان اسم مدينة موجودة بالحالة صدفة — تُترَك بالكامل لمسار modify_plan
  العادي (تعديل خطة فعلية قائمة، أو «ما في خطة لسا» إن لم توجد بعد).
  الغاية: تفادي تصادم مفردات (شيل/الغي تخدم كلا المسارين).
- **إعادة البدء الكاملة (إجراء غير قابل للتراجع → تأكيد إلزامي أولًا):** عبارات
  مثل «خطة جديدة»/«ابدأ من جديد»/«امسح كل شي»/new plan/start over **لا تُنفَّذ
  مباشرة** — يُطرح سؤال تأكيد صريح أولًا («متأكد بدك تبلش خطة جديدة؟ رح ننسى كل
  المعلومات...»). تأكيد إيجابي واضح (ايوا/أكيد/نعم/yes...) بلا نفي مرافق → مسح
  كامل لـ ConversationState وWorkingMemory (عدا اللغة) وإعادة طرح سؤال
  trip_purpose فورًا بنفس الرد. أي رد آخر (نفي أو غامض) → لا مسح إطلاقًا،
  استمرار عادي بنفس المعلومات المجموعة سابقًا.

## 3. خط معالجة الرسالة (بالترتيب الإلزامي)

```
رسالة المستخدم
  → [1] التطبيع + كشف اللغة
  → [2] حل الإشارات (قبل النية — قرار معماري مقصود)
  → [3] تصنيف النية (مع علامة __مكان_مشار_اليه__ إن وُجدت إشارة)
  → [4] استخراج الكيانات → تحديث الحالة
  → [5] مدير الحوار → القرار والاستدعاء
  → [6] مولّد الرد → تحديث ذاكرة العمل → الرد المنظم
```

### [1] المطبِّع
- توحيد: أ/إ/آ/ٱ → ا، ة → ه، ى → ي، إزالة التشكيل والتطويل.
- تقليص تكرار الأحرف (حلوووو → حلوو)، أرقام عربية → لاتينية، توحيد المسافات.
- كشف اللغة بعدّ أحرف كل أبجدية.

### [2] محلّل الإشارات — يبحث في (المقترحات + أماكن الخطة) معًا
بالترتيب:
1. **ترتيبية:** الأول/التاني/الثاني/التالت/الأخير/first/second/last/1/2/3
   → الموقع في last_recommendations.
2. **اسم صريح بمطابقة غامضة (rapidfuzz، عتبة 82):** على الاسمين العربي والإنكليزي،
   يتحمل الأخطاء («قلعه الحصن») والأسماء الجزئية («الحصن»، «krak»).
3. **ضمير:** هاد/هذا/هيدا/ياه/عنه/فيه/منه/it/this/that one
   → last_mentioned_place.

### [3] مصنّف النية
- 9 نوايا مغلقة (انظر CLAUDE.md) + unclear عند ثقة < 0.45.
- TF-IDF بمقاطع حروف char_wb مدى (2,5) + LogisticRegression — محايد للغة.
- عند وجود إشارة محلولة: يُلحق النص بعلامة `__مكان_مشار_اليه__` قبل التصنيف،
  وبيانات التدريب تحوي أمثلة بهذه العلامة («شو قصه __مكان_مشار_اليه__» → details).

### [4] مستخرج الكيانات (قواميس + أنماط)
- **مدن:** دمشق (الشام/damascus)، حلب (aleppo)، اللاذقية (الاذقيه/latakia/lattakia)،
  طرطوس (tartus)، حمص (homs)، حماة (hama)، السويداء، دير الزور، بصرى... **وجهة واحدة
  أو أكثر بنفس الرسالة** («دمشق وحلب» → destination=["دمشق","حلب"])، وتتراكم عبر
  الأدوار كالاهتمامات تمامًا (لا تُستبدَل — قاعدة الوراثة).
- **مدة:** أرقام + كلمات (يوم واحد/يومين/تلات أيام/ثلاثة أيام/أسبوع=7).
- **تاريخ بدء الرحلة (اختياري تمامًا — لا يُسأل عنه أبدًا، فقط إن ذُكر):** نسبي
  (بكرا/الاسبوع القادم/الشهر القادم/بعد N يوم أو اسبوع — أرقام أو كلمات مكتوبة)
  أو صريح (20 اكتوبر/5 تشرين الأول — أسماء الأشهر الميلادية والشامية معًا). يُحسب
  `dates.end` تلقائيًا بمعرفة `duration_days` الموروثة، ويُعاد حسابه إن تغيّرت
  المدة لاحقًا. **تنبيه تنفيذي:** «بعد N يوم/اسبوع» يجب استثناؤه من مطابقة نمط
  المدة (duration) صراحة كي لا يُقرأ «بعد 5 ايام» كمدة رحلة 5 أيام سهوًا.
- **مجموعة:** family (عيله/أطفال/ولاد/kids)، friends (أصحاب/شباب/رفقات/أصدقاء/
  رحلة تخرج/graduation)، couple (زوجتي/خطيبتي/مرتي/wife/honeymoon/شهر عسل/
  ذكرى زواج/anniversary)، solo (لحالي/وحدي/alone)، large_group (رحله جماعيه/
  مجموعه كبيره). **المناسبات الخاصة (شهر عسل، ذكرى زواج، رحلة تخرج) لا تُعامَل
  كحقل مستقل — تُطوى مباشرة على group_type الموجود** (شهر عسل/ذكرى زواج →
  couple، رحلة تخرج → friends).
- **استخراج متعدد بنداء واحد:** رسالة تحمل أكتر من معلومة («اريد الذهاب لدمشق
  مع اصدقائي» = وجهة + مجموعة معًا) تُستخرج كلها بنداء extract_entities واحد —
  كل كاشف (مدينة/مدة/مجموعة/ميزانية/اهتمامات) مستقل ويُشغَّل دائمًا بغض النظر
  عمّا اكتشفه غيره.
  قرار مقصود لتفادي حقل/نية جديدة لا تُغيّر مخرجات الـ mock فعليًا.
- **ميزانية:** low (اقتصادي/رخيص/على قد الحال/cheap)، high (فخم/فاخر/luxury).
- **اهتمامات → الوسوم الموحّدة** (قاموس CLAUDE.md). **تفضيل الجو/الهروب من الطقس
  لا يُنشئ وسمًا جديدًا ولا حقلًا جديدًا** — يُطوى على وسمين موجودين: عبارات
  البرد/الجبل/الهروب من الحر (جو بارد/هروب من الحر/cool weather) → tag:nature،
  وعبارات الدفء/الشمس (دافئ/شمس/warm weather/sunny) → tag:sea.

## 4. دليل قرار الاستدعاء (مرجع مدير الحوار — يُنفَّذ حرفيًا)

| النية | الاستدعاء | السلوك |
|---|---|---|
| **search** | فحص اكتمال الملف فقط — **لا استدعاء لـ `recommender.search` إطلاقًا** | **اجمع فقط، لا تستدعِ ولا تعرض** (قرار المالك): المطلوب = trip_purpose + destination + interests + budget_level + group_type (trip_purpose أعلى أولوية — حقل مستقل يُسأل عنه دائمًا، docs/contract.md §1.1). ناقص؟ → **سؤال واحد** عن أعلى ناقص أولوية (بهذا الترتيب) ويُعلَّق المسار (pending) ليُستأنف الجواب المقتضب. مكتمل (أو تهرّب مرتين → نتوقف بما توفّر ونصرّح)؟ → **تأكيد جاهزية نصّي فقط** (بلا بطاقات) — ConversationState المتراكمة هي "الناتج" الجاهز للتسليم لطبقة التوصية لاحقًا. |
| **details** | `recommender.details` فقط | الهدف = الإشارة المحلولة أو last_mentioned_place. إن غاب: «عن أي مكان بالضبط؟». **لا يُستدعى التخطيط ولا تُطرح أسئلته أبدًا.** يُسجَّل المكان كآخر مذكور. إن وُجدت خطة: ربط بجملة («وهو بيومك الأول الساعة 9»). |
| **compare** | `recommender.compare` | الأهداف بالإشارات (قد تكون ترتيبية: «الأول ولا التالت»). عرض جدول محاور + توصية مرجَّحة معلَّلة + القرار للمستخدم. **لا تخطيط.** |
| **build_plan** | فحص اكتمال الملف فقط — **لا استدعاء لـ `planner.build`/`planner.feasibility` إطلاقًا** | **اجمع فقط، لا تستدعِ ولا تعرض** (قرار المالك): المطلوب = trip_purpose + destination + interests + budget_level + group_type + duration_days. ناقص؟ → **سؤال واحد** بالترتيب (الهدف → المدينة → التصنيف → الميزانية → المجموعة → المدة) ويُعلَّق المسار. مكتمل (أو تهرّب مرتين → نتوقف بما توفّر ونصرّح)؟ → **تأكيد جاهزية نصّي فقط** (بلا خطة معروضة) — ConversationState المتراكمة هي الناتج الجاهز للتسليم لطبقة التخطيط لاحقًا. تاريخ البدء (dates)، وسيلة النقل (transport_mode)، والروتين اليومي (preferred_time) اختيارية تمامًا — تُستخرج فقط إن ذُكرت، لا يُسأل عنها أبدًا. |
| **modify_plan** | `planner.modify` فقط | لا خطة حالية؟ → «ما في خطة لسا، نبني وحدة؟». نوع التعديل من قاموس أفعال: remove (شيل/احذف/الغي)، replace (بدل/غير)، move (انقل/حط بيوم)، shift_time (قدم/أخر)، add، change_pace، extend_days. الهدف بمحلّل الإشارات (يبحث بأماكن الخطة). غامض؟ → عرض أماكن الخطة + «أي واحد تقصد؟». **التعديل جراحي** + ذكر التغييرات الجانبية من حقل changes. |
| **add_to_plan** | تحديث saved + `recommender.log` | الهدف بالإشارة أو آخر مذكور. يُضاف لـ saved_place_ids + حدث added_to_plan (غير متزامن). |
| **reject** | `recommender.log(pass)` لكل المعروضات | تُضاف للمستبعدات. سؤال تشخيصي واحد: «شو يلي ما ناسبك: النوعيه، البعد، ولا شي تاني؟» وجوابه يعدّل الحالة فعليًا قبل إعادة search. **ممنوع تكرار نفس النوعية.** |
| **greeting_thanks** | `recommender.profile` عند بدء جلسة | ترحيب شخصي غير متكلَّف إن وُجد تاريخ («آخر مرة كنا عم نجهز خطة اللاذقية...»). |
| **out_of_scope** | لا استدعاء | اعتذار لطيف + إعادة توجيه: «متخصص بالسياحة داخل سوريا — بس لو ناوي رحلة بسوريا بساعدك فيها!». |
| **unclear** | لا استدعاء | رد توضيحي **مستنتج من السياق**: خطة معروضة → «بتقصد تعدل عالخطة؟»، مقترحات معروضة → «بتحب تعرف أكتر عن حدا منهن؟»، لا سياق → خيارات عامة (اقتراح/خطة). ممنوع «ما فهمت» الجافة. |

**قاعدة حاسمة:** الاستعلام المعلوماتي الصرف (details/compare/سؤال عن منطقة)
لا يستدعي التخطيط ولا يفتح أسئلته («كم يوم؟ شو ميزانيتك؟») إطلاقًا.

## 5. السيناريوهات المرجعية (حالات اختبار القبول — تُغطى كلها في tests/test_flows.py)

1. **استكشاف مفتوح:** «بدي سافر بس ما بعرف لوين» → profile + 3 اتجاهات متنوعة فورًا
   + سؤال واحد. ممنوع الاستجواب.
2. **طلب محدد:** «شو أحلى مطاعم بحلب القديمة؟» → search فورًا + بطاقات + خطوة تالية.
3. **تفاصيل فقط:** «شو أوقات دوام المتحف الوطني؟» → details فقط، لا تخطيط.
4. **مقارنة:** «يلي أحسن لعيلتي: قلعة الحصن ولا صلاح الدين؟» → compare + توصية معلَّلة.
5. **خطة من الصفر:** «اعملي خطة 4 أيام بدمشق لعيلة مع طفلين» → الحالة شبه مكتملة،
   سؤال واحد (التواريخ)، ثم search + build.
6. **خطة من اختيارات:** (6 محفوظات) «رتبلي هدول بخطة يومين» → feasibility ثم build،
   وعند التعارض: مصارحة بالخيارات.
7. **تعديل تفاعلي:** «شيل المتحف من اليوم التاني وحط شي للأطفال بداله» → modify فقط،
   جراحي، مع ذكر الأثر الجانبي.
8. **رفض وتشخيص:** «ما عجبوني هدول» → log(pass) + سؤال تشخيصي + معايير مختلفة فعلًا.
9. **أجنبي:** «Is Palmyra worth visiting?» → إنكليزي، صادق، عملي.
10. **عودة بجلسة جديدة:** «مرحبا» بعد أسبوع → profile + ترحيب شخصي بذكر آخر نشاط.

وسيناريوهات تسلسل السياق (جوهرية):
- search → «شو قصة **التاني**؟» (ترتيبي) → «حلو **ضيفو**» (ضمير) →
  «و**الأول** كمان» (ترتيبي) → «رتبلي ياهن بخطة يومين» (build بالمحفوظات).
- build → «remove **the museum**» (اسم بالإنكليزي من أماكن الخطة) →
  «خلي الغدا أبكر» (shift_time بلا هدف مكاني).
